# デュエル・マスターズ価格画面 引き継ぎ

この文書は、ウォークスルーHTMLを別のAIが一度で作成するための引き継ぎです。
既存の `duel-masters-mercari-price-research-decisions.md` と異なる内容がある場合、この文書の確定事項を優先します。

## 確定事項

### 作るもの

- PC向けの単一HTML。
- 管理者側と利用者側の両方を操作できるウォークスルー。
- バックエンド接続やデータ保存は行わない。
- 既存コードは変更しない。
- 現在の画面・バックエンドは未実装。公式サイトとメルカリのクローラー、表示用DBの基本テーブルは実装済み。
- 実装済み処理と、HTML内だけの仮操作を混同させない。ただし、実装状況の長い説明を各画面へ置かない。

### 役割

役割は管理者と利用者の2つ。管理者用の操作を利用者へ見せない。利用者のメルカリ収集設定を管理者用の操作として扱わない。

管理者が行うこと:

- 必要な時だけ、公式サイトの商品一覧をProductマスターへ同期する。定期実行はしない。
- 同期済みの商品から対象を選び、商品単位で公式サイトからカード情報を取得する。
- 商品一覧でカード情報の取得中、完了、失敗を確認する。

管理者が行わないこと:

- 商品内のカード名やカード画像を確認・編集すること。
- メルカリ検索の追加ワードや除外ワードを登録・編集すること。
- 利用者ごとの収集設定を閲覧すること。

利用者が行うこと:

- カード名でカードを探す。
- 継続して金額を見たいカードを選び、30分ごとの価格チェックを開始する。
- 価格チェック中のカードを、カード名検索と商品による絞り込みで探す。
- 自分の「メルカリ検索の追加ワード」と除外ワードを登録・編集する。
- 複数カードを選び、同じカード別除外ワードを一括で追加する。
- 現在価格、価格推移、金額の取得元を確認する。
- 価格チェックをやめる。

### 管理者の商品操作

- 「商品一覧を更新」と「商品を追加」は別の操作にする。
- 「商品一覧を更新」は、公式サイトの商品一覧をProductマスターへ同期する操作。管理者が必要な時だけ実行する。
- 「商品を追加」は、同期済みのProductから対象を選び、その商品に属するカード情報の取得を開始する操作。
- 管理者の商品一覧には、カード情報の取得を開始した商品だけを表示する。
- カード情報をまだ取得していない商品は、「商品を追加」の選択画面で検索する。
- 商品一覧では取得中、完了、失敗を確認できるようにする。
- 商品一覧にカード数を表示しない。
- 取得ステータス専用画面やジョブログ画面は作らない。
- 「公式サイトから取得」のように対象が曖昧なボタン名を単独で使わず、商品一覧の同期か、選択した商品のカード取得かが分かる文言にする。
- Productマスターを同期するバックエンド処理は未実装であり、HTML内では仮操作として表現する。

### カードと収集設定

- 公式カードIDごとに別のカードとして扱う。同じカード名でも公式カードIDが異なれば別カードである。
- 公式カードIDは画面へ表示しない。同名カードはカード画像で選べるようにする。
- 公式カードIDから「シークレット」「金トレジャー」等の意味を自動判別できないため、そのような表示名を推測して追加しない。
- 利用者1人につき、1つの公式カードIDで現在使用する収集設定は1件だけとする。
- カードを選んだ時点で、公式カード名と利用者の共通除外ワードを使って価格チェックを開始する。選択時に追加設定を要求しない。
- 追加の設定は、価格チェック中の一覧にある編集操作から行う。
- 公式カード名はメルカリ検索に必ず使用し、利用者は変更できない。固有名詞として扱い、語順を並べ替えない。
- 利用者が入力する項目名は「メルカリ検索の追加ワード」のように用途を明示する。「検索語」だけのラベルは使わない。
- メルカリ検索の追加ワードは最大3単語。
- 追加ワードと除外ワードは内部で単語単位に正規化し、比較用の順番を統一して重複を除く。入力順が違うだけの同一条件は、利用者をまたいで1回だけクロールする。

### 除外ワード

- 除外ワードは利用者が設定する。管理者には設定させない。
- 除外ワードは1カードにつき3枠固定。この3枠のうち、共通除外ワードで指定した単語が先に埋まり、残った枠にカード別追加除外ワードを入れる。合計は3単語であり、共通とカード別で6単語にはならない。
- 共通除外ワードの初期値は「まとめ」「専用」の2枠、残る1枠は空欄。初期値を暗黙に適用せず、利用者が確認・編集できる状態で表示する。
- 共通除外ワードの変更は、その利用者が価格チェック中のすべてのカードへ即時同期する。カード別編集画面の共通枠にも同じ値が表示される。共通枠は共通除外ワード画面でだけ編集する。
- 利用者は複数カードを選び、カード別追加除外ワードを一括で追加できる。
- 「まとめて設定」だけでは何が変更されるか分からないため、「選択したカードに除外ワードを追加」のように対象と変更内容を明示する。共通枠で埋まっているスロットは一括追加や個別編集でも上書きしない。
- 一括追加によって除外ワード3枠を超えるケースは、今回のウォークスルーで発生させない。上限超過時のバックエンド処理は未決だが、HTML修正の前提条件ではない。

### クロール共有・停止・履歴

- 正規化後の収集条件が同じ場合、複数利用者で1つのクロールを共有する。利用者数に応じてクロール回数を増やさない。
- 同じ条件を見ている利用者が1人でもいる間は、30分ごとのクロールを継続する。
- 1人が価格チェックをやめても、別の利用者が同じ条件を見ていれば停止しない。
- 最後の利用者が価格チェックをやめた時点で新しいクロールを停止する。
- クロールを停止しても過去の価格履歴と収集設定は削除しない。同じ条件が再び選ばれた場合は履歴を引き継いで再開する。
- 既存の共有条件を新しく選んだ利用者にも、その利用者が選ぶ前から蓄積されている履歴を表示する。
- 追加ワードを変更した場合は別の収集条件として履歴を分け、現在の価格グラフへ混在させない。以前と同一の追加ワードへ戻した場合は以前の履歴を再利用する。
- 除外ワードの変更は調整として扱い、変更前後の価格履歴を1つのグラフへ連続して表示する。変更位置の注記は表示しない。
- 価格チェック開始直後に即時クロールするか、次の30分周期を待つかはバックエンドの未決事項。ウォークスルーでは具体的な待ち時間を断定しない。

### 画面上の情報

- `SearchCondition` という語は画面へ表示しない。
- 利用者へ、他の利用者の設定、内部状態、保存先などの技術情報を見せない。
- 利用者自身が編集する追加ワードと除外ワードは、設定編集画面に表示する。価格詳細の主要情報にはしない。
- 利用者がカードを選ぶ操作は、単なるブックマークではない。そのカードの継続的な価格収集を開始する操作である。
- 「お気に入り」「保存」は上記の意味とずれるため採用しない。
- 価格履歴は無期限保持する。7日間だけに限定しない。
- メルカリ検索結果画像の保持は3日間。3日より古い価格履歴は見られるが、対応する画像は残らない。

価格詳細で常に優先して見せるもの:

- カード名と画像。
- 現在価格。
- 価格推移。
- グラフで選択した時点の日時、価格、メルカリ検索結果画像。

グラフ上の時点を変更したら、日時、価格、メルカリ検索結果画像を同じ時点へ連動して切り替える。

価格詳細へ常設しないもの:

- 「取得日時」「算出方法」「対象」「画像の保存期間」を並べた説明欄。
- 検索結果1ページ目という内部仕様。
- 画像表示の制約に関する常設の注意書き。

古い時点を利用者が実際に選び、画像が残っていない場合にだけ、その旨を表示する。

### 画面設計の方針

- 説明文を足して理解させない。なくても伝わるラベルを使い、不要な線、集計、補足は削る。
- 最も重要な情報を大きさ、位置、余白で優先する。
- DBの値や内部用語をそのまま表示しない。
- 操作できるものは、説明文ではなく見た目で操作可能と分かるようにする。
- 管理者画面と利用者画面で同じデータを使っても、目的が違うため表示内容を分ける。
- ダミーデータはデュエル・マスターズの商品・カードとして自然な内容にする。

## HTML作成を止める未決事項

なし。

バックエンドのDB構造、正規化で文字種や空白をどこまで同一視するか、一括追加の上限超過処理、価格チェック開始直後のクロール時期は未決だが、上記の指示に従えばウォークスルーHTMLを作成できる。これらをHTML作成者が独自に確定したり、説明文として画面へ追加したりしない。

## HTML作成者が決めてよいこと

以下は先に確定しなくてもHTMLを作成できる。利用場面と画面設計の方針に従い、HTML作成者が自然な案を選んでよい。

- ボタン、ナビゲーション、画面タイトルの具体的な文言。
- 価格収集を開始する操作の短い名称。
- 価格推移の初期表示期間と期間選択肢。
- 管理者側と利用者側をウォークスルー内で切り替える方法。
- カード一覧を表、リスト、カードのどの形式で表現するか。
- 配色、余白、文字サイズ、アイコン。
- トースト、入力画面、確認表示などの細かな動作。

文言はHTML作成の前提条件ではない。内部用語を避け、利用者の行動が伝わる短い言葉をHTML作成者が選ぶ。

## この文書に書かれていない機能を追加してはいけない

以下は過去に無断で追加してしまい、この文書の要件にはない。含めない。

- 利用者側の文明フィルタ、および文明ラベル表示。利用者はカード名で探す。文明で絞る要件はない。
- 管理者の取得ステータス専用画面、ジョブログ画面。
- 管理者の商品一覧にあるカード数。
- 管理者が商品内のカード名やカード画像を確認する画面。
- 管理者がメルカリ検索の追加ワードや除外ワードを編集する画面。
- 管理者向けの共通・一括・個別収集設定画面。
- 「シークレット」「金トレジャー」等、公式カードIDから推測した表示名。
- 共通設定画面の検索ワードテンプレート。
- 共通設定画面の影響メトリクスカード。
- 利用者サイドバーの「最近見た価格」。
- 利用者側の「共有」ボタン。

「あると自然かも」「デュエマらしいから」で機能を足さない。この文書の「作るもの」「役割」「画面上の情報」「収集設定」に書かれた項目だけを実装する。判断に迷う項目は追加前に確認する。
